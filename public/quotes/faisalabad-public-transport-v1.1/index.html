Discovery questions

What we need to confirm with you

Select any question and we will walk through what it means and why it matters.

We have sized the platform and the servers for 600 vehicles. Confirming the real starting number, and the number you expect to reach later, fixes the server capacity and the monthly running cost so neither is over-bought.
The driver phone starts tracking immediately with no hardware to buy and no SIM per vehicle. A fixed 4G tracker works independently of the driver but must be procured, fitted and given its own SIM. Our recommendation is to start with phones and add trackers in Phase 2 only where they are genuinely needed.
If routes and stops already exist as maps, spreadsheets, or even GPS logs from a survey, we import them directly. If they do not exist, they have to be surveyed and digitised first, and that changes the Phase 1 timeline. This is usually the single biggest unknown.
For example government buses, urban Hiace, and metro service. Each category can have different routes, different operators and different permissions, which shapes the dashboard and how drivers are onboarded.
We set access by role. An operator can be limited to seeing only their own vehicles, while the authority sees the whole network and can edit routes and stops. Telling us the roles now avoids rework later.
This is Phase 3 work. Knowing early whether you need 1Link, JazzCash, cards, or a combination tells us which integrations and which bank approvals to begin, because those approvals take time on the client side.
Hosting location affects both cost and compliance. In every case the spatial database and the source code remain owned by the department, not held inside a third-party service.
A tender needs compliance documents and a formal bid pack, which we prepare. A direct contract can begin as soon as Discovery is signed off. Both are fine, we simply need to know which one to prepare for.
